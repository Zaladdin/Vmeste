# Регистрация и отправка писем

## Почему возникает ошибка

`over_email_send_rate_limit` означает, что Supabase Auth исчерпал общий лимит писем подтверждения проекта. Это не ошибка пароля и не запрет регистрации в интерфейсе. Повторные попытки не снимают ограничение. `email_address_not_authorized` означает, что встроенная почтовая служба не принимает адрес получателя.

По документации Supabase встроенная служба предназначена для тестирования, отправляет письма только разрешённым адресам команды и ограничена двумя письмами в час на проект. Для регистрации друзей с произвольными адресами требуется собственный SMTP или Send Email hook:

- https://supabase.com/docs/guides/auth/auth-smtp
- https://supabase.com/docs/guides/auth/rate-limits

## Рекомендуемая настройка

1. Получите SMTP-параметры у выбранного почтового провайдера: host, port, user, password, подтверждённый адрес отправителя.
2. В Supabase откройте Authentication → Emails → SMTP Settings и включите собственный SMTP.
3. Введите параметры напрямую в панели Supabase. SMTP-пароль не должен попадать в клиентский JavaScript, GitHub Pages, публичный репозиторий или чат.
4. Сохраните настройки, оставив подтверждение email включённым. Проверьте адрес сайта и разрешённый redirect URL `https://zaladdin.github.io/Vmeste/`.
5. Проверьте регистрацию одним разрешённым тестовым адресом и переход по письму. При необходимости согласуйте лимиты Supabase Auth и почтового провайдера.

## Закрытое тестирование без писем

Только после явного выбора владельца проекта можно временно отключить Confirm email в Authentication → Sign In / Providers → Email. Тогда новый пользователь сможет зарегистрироваться без подтверждения владения адресом, в том числе указать чужой адрес. Это не заменяет SMTP для публичной регистрации.

Приложение не отключает подтверждение автоматически и не обходит ограничения Supabase. Привязка участников комнаты остаётся по UUID аккаунта и выполняется организатором, а не по совпадению email или имени.

## Проверка удаления комнат

Удаление и исключение участника теперь подтверждаются кнопками внутри приложения. Они не используют `window.confirm`, который может быть недоступен во встроенном браузере. Отмена не вызывает RPC; подтверждение вызывает защищённую серверную функцию. Личная поездка и оригиналы документов остаются в хранилище аккаунта.
