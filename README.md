# Вместе

Локальная первая версия органайзера совместных путешествий. Next.js App Router, React, TypeScript, IndexedDB (`idb`), Zod, Temporal, Lucide. Интерфейс на русском, адаптирован для телефона.

## Бесплатный сайт для телефона

Адрес GitHub Pages: **https://zaladdin.github.io/Vmeste/**. Откройте в Safari/Chrome на телефоне; через меню браузера можно добавить на главный экран. После первого открытия и сообщения «Можно открыть без интернета» план доступен офлайн.

На GitHub Pages доступны поездки, ручное добавление событий, документы, карты и экспорт/импорт плана. Поездки и документы остаются в IndexedDB конкретного браузера: они не публикуются в GitHub и автоматически не синхронизируются с компьютером. Экспорт JSON переносит план без вложенных файлов; оригиналы билетов переносите отдельно. Очистка данных браузера удаляет локальные данные.

GitHub Pages раздаёт статические файлы и не запускает Codex CLI. Без облачной конфигурации AI-контролы отключены и запросы к отсутствующему API не отправляются. Подготовлен дополнительный режим: личный вход Supabase, закрытая очередь и локальный обработчик Codex на включённом компьютере. Настройка и ограничения — [docs/cloud-setup.md](docs/cloud-setup.md). Этот режим передаёт документы и результаты распознавания, но пока не синхронизирует все поездки между устройствами.

### Публикация и обновления

В репозитории Settings → Pages → Source выберите **GitHub Actions**. Workflow `.github/workflows/pages.yml` при push в `main` запускает тесты, собирает сайт и публикует его. Настройка Pages уже включена для этой репозитории. Для локальной проверки экспорта:

```powershell
npm ci
npm run build:pages
```

Результат — `out/` с путями `/Vmeste/`. Скрипт собирает отдельную временную копию без API-маршрутов, `.env`, счётчиков и локальных пользовательских данных, не меняя серверную версию проекта. Другому имени репозитория соответствует `NEXT_PUBLIC_BASE_PATH` в workflow. В Git не входят `.local`, `.env.local`, node_modules, сборки и out; `.env.example` содержит только пример настроек.

Для следующего этапа с общей базой подходят Vercel Hobby (личные некоммерческие проекты) и Supabase Free. У бесплатных тарифов есть квоты; AI-обработка оплачивается отдельно. Render Free подходит для экспериментов с backend, но сервер засыпает после простоя, а локальный диск не сохраняется между перезапусками — нынешний файловый счётчик перед таким переносом нужно заменить постоянным хранилищем.

## Запуск

Требуется Node.js 22.19+ и npm. Зависимости зафиксированы в `package-lock.json`.

```powershell
npm ci
npm run dev
```

Открыть http://127.0.0.1:3000. Для проверки офлайн-режима использовать production-сборку:

```powershell
npm run build
npm start
```

Не запускайте dev и production одновременно на одном порту.

## Что работает

- Создание, редактирование и удаление поездок; пример Стамбула создаётся один раз.
- План по дням, перелёты, проживание, переезды и прогулки. События сортируются по реальному моменту времени, отображаются с местным временем. У перелёта отдельные часовые пояса начала и окончания. Неоднозначное и несуществующее время перехода на летнее время отклоняется.
- На следующих днях показывается продолжающееся проживание и время выселения.
- Локальный список участников и привязка участников к событиям.
- Настоящие файлы PDF/JPEG/PNG/WebP до 20 МиБ, сохранение в IndexedDB, привязка к событию, скачивание и удаление.
- При загрузке билетов и бронирований — распознавание через локальный Codex CLI с существующим входом ChatGPT и автоматическое добавление отдельных перелётов, переездов и проживания. Документ связывается со всеми найденными событиями. Неполные/сомнительные данные сохраняются для уточнения; даты поездки расширяются только после подтверждения.
- Повторные файлы определяются по SHA-256, совпадающие события не добавляются повторно. Ошибка API не удаляет файл: доступна повторная попытка. После удаления события его можно восстановить из сохранённого распознавания через «Уточнить».
- Список мест с внешними ссылками на Google Maps.
- Экспорт и импорт JSON-плана до 16 МиБ. Импорт создаёт отдельную поездку с новыми идентификаторами и связями участников. **Документы в JSON не входят.**
- В production Service Worker сохраняет оболочку приложения, JS/CSS и обложку. После сообщения «Можно открыть без интернета» план и документы можно открывать без сети. Внешние карты требуют подключения.

## Где хранятся данные

Только на устройстве, в IndexedDB этого браузера и origin. Другой браузер, порт, hostname или устройство имеет отдельное хранилище. Очистка данных сайта удаляет поездки и документы. Экспортируйте план и храните оригиналы файлов отдельно. Это первая локальная версия, а не долговременное облачное хранилище.

Приглашения и общая синхронизация между устройствами ещё не реализованы. Добавление имени не отправляет приглашение. Дополнительная очередь Supabase требует применения миграции и входа владельца; без настройки работает прежний локальный режим. Для распознавания документ передаётся в Codex через локальный сервер, напрямую либо через закрытую очередь; эту обработку можно отключить флажком перед загрузкой. Само распознавание выполняется облачной моделью и требует интернета.

## Настройка распознавания

### Дневной лимит и оценка кредитов

В разделе документов до выбора файла показываются дневной лимит и ориентир ≈0,65 кредита за одну попытку через Codex GPT‑6.1 Sol Standard (по тестовому билету). Это оценка, а не гарантированная стоимость или жёсткий денежный предел. Другие документы/модели могут стоить дороже; баланс аккаунта автоматически не считывается приложением.

По умолчанию разрешено 10 попыток модели в сутки, общий лимит всех поездок этого локального сервера. Его можно изменить в интерфейсе от 0 до 100; 0 приостанавливает распознавание. Сброс в 00:00 UTC (04:00 в Баку), точное время показывается в локальном часовом поясе браузера. Начальный лимит можно задать `VMESTE_DAILY_RECOGNITION_LIMIT`, сохранённые настройки имеют приоритет.

Каждый запуск модели предварительно занимает одну попытку на сервере: текст и последующий переход к изображениям занимают две, ручной повтор — ещё одну. Неудачный запуск тоже учитывается консервативно, поскольку мог уже расходовать токены. При исчерпании лимита новые документы сохраняются без распознавания. Счётчик и настройка сохраняются в `.local/recognition-budget.json` и переживают перезапуск; вкладки браузера не получают отдельный лимит. Ограничение распространяется на Codex и альтернативный API-провайдер, но показанный ориентир кредитов относится только к указанной модели Codex.

Повреждённый/недоступный счётчик блокирует новые вызовы модели. Если после аварийного завершения остаётся ошибка блокировки, остановите **все** экземпляры сервера этого проекта, удалите **только** `.local/recognition-budget.lock`, затем запустите сервер снова. Файл `.local/recognition-budget.json` сохраняйте — его удаление уничтожит счётчик и настройку. Активная блокировка автоматически не удаляется, чтобы параллельные процессы не обходили лимит.

Процесс распознавания использует короткие доверенные инструкции для извлечения бронирований вместо встроенных инструкций Codex для работы с кодом (`model_instructions_file`, `personality=none`). Файл создаётся только в отдельном временном каталоге конкретного запроса; выбранная модель и reasoning сохраняются. Общий config.toml не меняется. Правила извлечения, строгая схема, запрет инструментов и проверка недоверенных документов сохранены. На одном контрольном билете общий расход сократился с 19 881 до 12 065 токенов (39,3%); это результат конкретного сравнения, не гарантия для всех документов. Подробности — `docs/codex-context-optimization.md`.

PDF через Codex сначала проверяется в изолированном Worker: если на всех страницах есть читаемый текст без изображений и он укладывается в 40 000 символов, распознаётся текст. Для сканов, смешанных/нечитаемых PDF используется прежнее распознавание изображений. Если текстовый результат пуст, содержит предупреждения, требует уточнения или имеет неполное/некорректное расписание, выполняется дополнительная попытка по изображениям. В этом случае расход включает обе попытки, если доступны оба фактических счётчика. Ошибки аккаунта не вызывают повторную попытку. Повреждённый PDF не принимается частично. Экономия токенов не гарантируется: в контрольном сравнении этого билета текстовый путь израсходовал больше токенов.

Для новых успешных распознаваний через Codex расход токенов сохраняется рядом с документом: вход, выход и доступное число входных токенов из кэша. Всего = вход + выход; кэш повторно не прибавляется. Источник — фактическое событие CLI `turn.completed.usage`, а не оценка модели. Если счётчиков нет, число не показывается. Для старых документов расход задним числом не восстанавливается. Это токены запроса распознавания, включая его служебный контекст; они не задают фиксированную стоимость в кредитах.

По умолчанию `VMESTE_RECOGNITION_PROVIDER=codex`. Требуются установленный Codex CLI и вход через ChatGPT (`codex login`; проверить можно `codex login status`). Используется существующий локальный вход, расходуются его лимиты/кредиты. API-ключ не требуется. Если `codex` отсутствует в PATH сервера, задайте `CODEX_EXECUTABLE` абсолютным путём к настоящему исполняемому файлу (на Windows `.exe`).

Для отдельного вызова CLI настройки плагинов/хуков не загружаются, shell и другие инструменты отключены, sandbox read-only; глобальные настройки пользователя не меняются. Корневые `model` и `model_reasoning_effort` сохраняются из пользовательского config.toml. API-ключи и переменные gateway не передаются дочернему процессу. Файлы авторизации не читаются и не копируются приложением. Изображения и схема размещаются в отдельной временной папке и удаляются после завершения/ошибки. Вывод проверяется строгой схемой, неожиданные действия CLI прекращают распознавание. Это интеграция для личного локального использования, а не публичный сервис с доступом к аккаунту владельца.

PDF преобразуется в PNG в отдельном Node Worker: максимум 8 страниц, 1800px по длинной стороне, ограничение суммарных пикселей/размера и 30 секунд на подготовку. Все страницы обрабатываются либо файл отклоняется целиком; защищённый паролем или повреждённый PDF просит загрузить подходящую копию/изображения. Корректные пустые страницы допустимы. JPG/PNG/WebP принимаются до 24 мегапикселей. Codex получает до 180 секунд на распознавание; весь клиентский запрос ограничен 240 секундами. Оригинал документа всегда остаётся в IndexedDB при ошибке. PDF.js закреплён на версии 6.4.299: обход ошибки частичного operator-stream использует проверенный внутренний интерфейс и должен повторно тестироваться при обновлении библиотеки.

Старый API-способ сохранён как явная альтернатива: `VMESTE_RECOGNITION_PROVIDER=openai`, серверная переменная `OPENAI_API_KEY` и опциональная `OPENAI_RECOGNITION_MODEL` (по умолчанию `gpt-5-mini`). Храните ключ в окружении или `.env.local`, не в клиентском коде и не в чате. Имена переменных приведены в `.env.example`; ключи в репозиторий не сохраняются. В этом режиме требуются отдельные лимиты/баланс API, запрос отправляется со `store:false` (это не означает отсутствия всех видов хранения у провайдера). Автоматического переключения на платный API после ошибки Codex нет.

`POST /api/recognize` принимает multipart-файл до 20 МиБ и не сохраняет его на диск сервера. Проверяются сигнатура формата, размер потока, прямой Host, Origin и заголовок намерения. Текущая версия намеренно разрешает только loopback-адреса (localhost / 127.0.0.1 / ::1); перед публичным размещением потребуются авторизация, распределённые лимиты и соответствующая политика доступа. Локальные лимиты: два одновременных запроса и десять в минуту.

Часовые пояса определяются по явно указанным данным или однозначной географии. Неизвестные даты/время не заменяются стандартными значениями. При неуверенности требуется проверка. AI может ошибаться даже при полном результате — даты и время остаются редактируемыми в плане. Распознавание не возобновляется автоматически после закрытия вкладки: повторите его кнопкой у документа; незавершённую попытку можно перезапустить через 260 секунд.

## Структура

- `src/app` — страница, метаданные и стили.
- `src/components/travel-app.tsx` — состояние приложения, переключение поездок, сохранение и экспорт.
- `src/components/editors.tsx` — формы поездки, событий и участников.
- `src/components/timeline.tsx` — расписание и места.
- `src/components/documents.tsx` — настоящие локальные файлы.
- `src/lib/model.ts` — схемы данных, даты, часовые пояса, обмен JSON.
- `src/lib/storage.ts` — транзакции IndexedDB и связи документов.
- `src/lib/recognition.ts` — схема результата и преобразование в события без выдуманных значений.
- `src/lib/recognition-server.ts`, `src/app/api/recognize/route.ts` — серверная интеграция с OpenAI.
- `src/lib/codex-recognition.ts` — изолированный запуск CLI с авторизацией ChatGPT.
- `src/lib/document-images.ts`, `src/lib/pdf-render-worker.mjs` — ограниченное преобразование документов в изображения.
- `src/components/recognition-review.tsx` — проверка и исправление неполных результатов.
- `public/sw.js` — офлайн-оболочка; `design/concept.png` — визуальный концепт.

Модели поездок отделены от хранения. Для полной синхронизации нужно дополнительно подключить облачный репозиторий поездок с версионированием и подписками. Подготовленные Auth/RLS и очередь относятся к личному распознаванию, а локальный список участников не является механизмом приглашений или авторизации.

## Проверки

```powershell
npm run typecheck
npm test
npm run test:coverage
npx prettier --check src public/sw.js public/manifest.webmanifest package.json tsconfig.json vitest.config.ts next.config.ts
```

Покрытие измеряется для модели, репозитория и модулей распознавания, включая API-обработчик; оно не является оценкой покрытия UI. В unit-тестах OpenAI подменён контролируемыми ответами: тесты не расходуют баланс. Результаты браузерных проверок и ограничения — в `docs/verification.md`.

Официальные источники интеграции: [Codex non-interactive](https://learn.chatgpt.com/docs/non-interactive-mode), [CLI](https://learn.chatgpt.com/docs/cli/reference), [API PDF](https://developers.openai.com/api/docs/guides/file-inputs), [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).
