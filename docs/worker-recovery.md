# Восстановление запуска обработчика

28 октября 2026. Первый этап `docs/roadmap.md`: повторный запуск после сбоя
без ручного удаления файла блокировки. Статус на телефоне и восстановление
облачных заданий остаются отдельными задачами.

Сценарии: владелец может перезапустить завершившийся процесс; второй процесс
не получает право работать одновременно; проверка статуса не вызывает модель.

## Изменение

Старое `open(..., "wx")` принимало оставшийся файл за действующий процесс.
Теперь ядро ОС удерживает локальный сокет на протяжении жизни обработчика.
Служебный файл остаётся на месте; повторный запуск не требует его удаления.
Флаг `--recover-lock` нужен только для явного перехода старого/повреждённого
формата после остановки старых обработчиков. Занятый порт никогда не обходится.

Распознавание, дневной счётчик и облачные переходы заданий не изменены.
Платные вызовы после неизвестного результата автоматически не повторяются.

## TDD и проверки

Первый запуск `npm test -- src/lib/cloud-worker-lock.test.ts` завершился RED:
новый модуль блокировки ещё не существовал (`Cannot find module`). После
реализации тот же набор прошёл GREEN.

Одиннадцать проверок покрывают конкурирующие запуски, запрет второго процесса
даже с `--recover-lock`, штатный перезапуск, обязательный явный переход старого
формата, повреждённый формат, статус без записи файлов, занятый посторонним
приложением порт, освобождение при ошибке записи метаданных и реальное
принудительное завершение дочернего Node-процесса. Дополнительно проверены
ошибка чтения метаданных и закрытие входящих соединений без API.

Случайные временные каталоги тестов могут соответствовать зарезервированным
Windows портам. Только тестовые фикстуры выбирают другой свободный namespace;
производственный код никогда не меняет порт для обхода блокировки.

Checkpoint-коммиты не создавались: пользовательский workflow запрещает
автоматические коммиты по требованию upstream-навыка. Реальное покрытие этого
модуля проверено отдельно командой
`npm test -- src/lib/cloud-worker-lock.test.ts --coverage --coverage.include=scripts/cloud-worker-lock.mjs`:
statements 96,42%, branches 80%, functions 100%, lines 96%.
Общий процент старой конфигурации этот модуль не включает.

Живой запуск `npm run worker -- --recover-lock` успешно прошёл вход и вывел
«Ожидаем задания». Для проверки не создавались новые задания распознавания.
Дальнейшие старты выполняются обычным `npm run worker`.
