# Распознавание на VPS без включённого компьютера

Сайт остаётся на `https://zaladdin.github.io/Vmeste/`, а VPS выполняет только
закрытые задания распознавания через существующую очередь Supabase. Next API
слушает `127.0.0.1` внутри контейнера и доступен только соседнему процессу
обработчика. Docker Compose не публикует порты. Публичный веб-доступ к Codex
и его аккаунту не создаётся.

Это подготовка развёртывания: наличие сервера, SSH-доступ, его тариф и успешный
вход в аккаунты нужно проверить отдельно. Здесь не создаётся сервер и не
гарантируется бесплатная инфраструктура. Практический ориентир для сборки —
Linux с Docker Compose, 2 CPU и 4 ГБ RAM; runtime ограничен 2 ГБ в compose.

## 1. Подготовить исходники и настройки

Перед переносом сохраните полную резервную копию поездки с документами из меню
приложения. План всё ещё находится в браузере: перенос обработчика не создаёт
автоматическую синхронизацию поездок между устройствами.

На VPS поместите проверенную версию исходников проекта. Не передавайте
`docs/*.pdf`, `.env.local`, `.local`, `node_modules`, `.next` или авторизацию
Codex с Windows. Allowlist в `.dockerignore` исключает их из контекста Docker,
но не делает безопасным произвольный архив или `git add .`.

Скопируйте `.env.server.example` в `.env.server` на сервере и укажите только
Project URL и публичный Publishable/anon key того же Supabase. `service_role`,
пароль базы и API-ключ OpenAI не нужны. Не меняйте права приватного Storage/RLS.
Файл `.env.server` уже исключён общим правилом `.env*` из Git.

```bash
chmod 600 .env.server
docker compose build worker
```

Образ собирает зависимости для Linux и устанавливает Codex CLI `0.165.0` внутри
образа. Локальная версия CLI на Windows не обновляется. Выбранные модель и
reasoning зафиксированы в `deploy/codex.config.toml`; при необходимости сверяйте
их с настройками своего аккаунта перед сборкой.

## 2. Войти в аккаунты на сервере

Пока не запускайте `docker compose up`. Одноразовые команды используют те же
именованные тома, что и постоянный сервис.

```bash
docker compose run --rm --no-deps worker codex login --device-auth
docker compose run --rm --no-deps worker codex login status
docker compose run --rm --no-deps worker npm run worker:login
```

Для Codex откройте показанную ссылку в своём браузере и самостоятельно введите
одноразовый код. Может потребоваться включить device-code login в настройках
аккаунта. Официальное описание: [OpenAI: Authentication](https://learn.chatgpt.com/docs/auth).
В `worker:login` войдите в тот же личный аккаунт приложения Supabase, что и на
телефоне. Пароль запрашивается интерактивно и не записывается в исходники.

Не присылайте пароли, device-коды и файлы авторизации в чат. Не копируйте
авторизацию Windows в Linux и не публикуйте тома. В Linux файлы сессий хранятся
в закрытых пользовательских каталогах; это файловое хранение, не Windows DPAPI.
Вход может потребовать повторения при отзыве/истечении сессии.

## 3. Перенести дневной счётчик до включения обработки

Новый сервер по умолчанию начинает с лимита **0**, то есть на паузе. Это не
дополнительные десять попыток при переносе. Существующий счётчик в томе имеет
приоритет над начальным значением окружения.

1. Остановите локальный обработчик на компьютере через Ctrl+C. Не запускайте
   одновременно локальную и серверную обработку: разные машины имеют разные
   локальные счётчики.
2. Убедитесь, что серверный сервис остановлен: `docker compose stop worker`.
3. Передайте по SSH/SCP **только** `.local/recognition-budget.json` с компьютера,
   например в закрытый `~/vmeste-budget.json` на VPS. Не копируйте lock-файлы.
4. Восстановите его от непривилегированного пользователя образа:

```bash
chmod 600 ~/vmeste-budget.json
docker compose run --rm --no-deps -T worker node scripts/run-remote-worker.mjs --restore-budget < ~/vmeste-budget.json
```

Команда проверяет формат/дату/числа, сохраняет `used`, `limit` и UTC-день целиком,
пишет файл атомарно и не запускает модель. Например, исчерпанные 10 из 10 остаются
исчерпанными до обычного сброса UTC-суток. Повреждённый файл не заменяет старый.
Не удаляйте счётчик для восстановления работоспособности.

Linux-команда запуска и восстановления сначала получает kernel-lock `flock` в
общем томе. Он не позволяет одноразовому контейнеру восстановления работать
параллельно с постоянным сервисом и освобождается ОС при завершении процесса.
Дополнительно берутся блокировка локального обработчика и та же блокировка
файла бюджета, что использует API. Уже использованный счётчик текущего дня
уменьшить нельзя; повреждённое существующее состояние не перезаписывается.

## 4. Запуск и проверка

```bash
docker compose up -d worker
docker compose ps
docker compose logs --tail=30 worker
docker compose exec worker codex login status
docker compose exec worker npm run worker:status
```

`worker:status` проверяет только локальную блокировку, а Docker healthcheck —
доступность приватного Next API. Ни одна проверка не доказывает успешное
распознавание или доступный баланс. Логи должны показать ожидание заданий либо
дневного лимита; не запускайте реальный платный документ только ради проверки.
Один согласованный тест после входа и миграции счётчика проверяется отдельно.

Сайт по-прежнему отправляет документ в Supabase, VPS забирает своё задание и
сохраняет результат. После выключения личного компьютера VPS должен оставаться
включённым. Стоимость/лимиты Codex и ограничения хостинга при этом сохраняются.

`restart: unless-stopped` перезапускает процессы после сбоя. Это не означает
повторного выполнения уже взятого задания: `processing` автоматически не
возвращается в очередь. Восстанавливайте его только явно по инструкции
`docs/cloud-setup.md`, поскольку предыдущая модель могла уже расходовать кредиты.

## Сохранение состояния и откат

Три именованных тома сохраняют дневной счётчик, вход Codex и сессию Supabase.
При обновлении используйте тот же Compose project name и те же тома; перенос
каталога/имени проекта может создать новые пустые тома. Сначала остановите старый
экземпляр, затем обновляйте один worker. Не масштабируйте сервис.

```bash
docker compose stop worker
docker image tag vmeste-worker:local vmeste-worker:previous
docker compose build worker
docker compose up -d worker
```

Для отката к сохранённому образу без пересборки:

```bash
docker compose stop worker
VMESTE_IMAGE_TAG=previous docker compose up -d --no-build worker
```

Не используйте `docker compose down -v`, не удаляйте тома и не подключайте их к
публичному файловому серверу. Резервные копии томов содержат авторизацию и требуют
такого же ограничения доступа, как пароли. План и билеты в браузере сохраняйте
через полный экспорт приложения отдельно.

## Проверки реализации

Supervisor проверяется с имитацией дочерних процессов и loopback-ответов:
ожидание готовности API до запуска очереди, остановка обоих процессов по сигналу,
выход с ошибкой при неожиданном завершении любого процесса, отсутствие локального
автоповтора обработки, точное восстановление счётчика и отказ неверной замене.
Тесты не обращаются к аккаунтам и модели. Реальное развёртывание и входы не
считаются выполненными до отдельной проверки на выбранном VPS.
